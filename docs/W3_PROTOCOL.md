# W3: noiseless equation-parameter identification across 50 cases

## Research question and data

W3 tests whether a model gives stable, accurate equation-parameter readouts as the true physical parameters vary. It does not position GIFT as a dedicated parameter-identification algorithm and includes no noise conditions. The 50 fixed parameter cases are generated by LHS seed2026100901: ν is log-uniform over [0.0075, 0.015], while β and γ are each linear over [0.75, 1.25]. The true equation is ω_t=−β(uω_x+vω_y)+ν∇²ω+γq, q=−4cos(4y).

Each parameter case corresponds to an independent N64 vorticity trajectory with local data ID0, spanning t=0–10 with 501 frames, output interval 0.02 and internal integration step 0.005. Each case uses only its own ID0 trajectory and has 0 additional validation trajectories. All parameter cases share the same initial-condition parameters, and each trajectory is generated under its own equation parameters. The design CSV SHA-256 is `43b8b7d0edb5d70f4b7c7519946c7e358e88011db582f09c5d7e6940f1893a14`.

## Methods and fixed budgets

The five methods are GIFT, PDE-FIND, PDE-FIND-KC, PINN-SR and PINN-SR-KC. Each method runs once for each of 50 cases, giving 250 unique method/case slots and 750 parameter readouts. There is no outer hyperparameter search, extra training seed, test-based tuning or replacement of failed slots.

| Method | Fixed main settings |
|---|---|
| GIFT | Independent training per case; seed2026072301; one training trajectory, zero validation trajectories; batch16, 6000+6000 updates, lr0.01/0.003, P21/rank8; terminal stage checkpoints; final affine fit and P21 parameter readout. |
| PDE-FIND | Independent derivatives and regression per case; open90-term library; seed0; local-polynomial and STRidge procedure, without SVD denoising. |
| PDE-FIND-KC | Independent derivatives and regression per case; known4-term library; seed0; local-polynomial and STRidge procedure, without SVD denoising. |
| PINN-SR | Fresh seed1234 per case, open90-term library, paper_ado_v1/native_fp32, TF32 disabled;24,000 training observations,6,000 same-trajectory holdout observations,84,000 physics points;5,000 joint NAdam updates, one actual SciPy L-BFGS call,6×1,000 network NAdam updates,20,000 final joint NAdam updates; terminal checkpoint. |
| PINN-SR-KC | The complete PINN-SR budget, with the known4-term library. |

PINN L-BFGS `maxiter` and `maxfun` are limits, with actual per-case termination reasons reported; reaching a limit does not imply convergence. PINN retains every candidate coefficient, the exact nonzero support from the final STRidge iteration and errors for each true term. Within-training GIFT monitoring is diagnostic only; terminal models are always used, without validation-based checkpoint selection.

Each method uses its own declared observation processing, identification objective and budget; this is not an equal-information/equal-budget architectural control. PDE-FIND variants have no neural-network training stage, and wall-clock costs across methods are not a ranking under a common hardware budget.

## Metrics and results

For truth θ and readout θ̂, report APE=100×|θ̂−θ|/|θ|. Each algorithm/parameter has 50 case-level readouts; the table summarizes the mean and median of these 50 APEs, without standard deviations across training seeds. The complete parameter design,750 readout rows,250 slot outcomes, coefficient supports, input/source hashes and actual costs are in the [W3 result package](../results/formal/W3_single_trajectory_20261010/README.md) and its `published.json` manifest.

| PDE-FIND | 97.41%(102.07%) | 10.94%(11.15%) | 7.57%(7.70%) |

All 250 instances completed, and all 750 parameter readouts are finite;0 execution failures does not imply accurate identification in every case. GIFT has the lowest mean APE for ν and β; PDE-FIND has the lowest for γ. GIFT's maximum ν APE is 59.32%, showing substantial bias for some parameter combinations. All 100 PINN L-BFGS calls reached the function/gradient-evaluation limit and then completed their prescribed subsequent budgets; these states cannot be called optimization convergence. Results are presented jointly through per-case values, summary tables and [Figure 4](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/w3_parameter_nu_errors.svg).

## Visualization of parameter errors

[Figure 4a: ν SVG](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/w3_parameter_nu_errors.svg) ([PNG](../assets/figures/w3_parameter_nu_errors.png)) · [Figure 4b: β SVG](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/w3_parameter_beta_errors.svg) ([PNG](../assets/figures/w3_parameter_beta_errors.png)) · [Figure 4c: γ SVG](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/w3_parameter_gamma_errors.svg) ([PNG](../assets/figures/w3_parameter_gamma_errors.png))

Figures 4a,4b and 4c show absolute percentage errors for ν, β and γ, respectively, APE_p=100×|p̂−p|/|p|, computed elementwise from the same 750 rows of truths and estimates. Each figure orders GIFT, PDE-FIND, PDE-FIND-KC, PINN-SR and PINN-SR-KC consistently, retaining all 50 actual readouts per method row,250 points total. Each dot's horizontal coordinate is that readout's APE. Dots are sorted by APE and placed deterministically on seven evenly spaced horizontal tracks, preferring central tracks without intersections with existing dots; dense values may still overlap. Nominal dot diameter is 2.1 pt and adjacent-track spacing is 2.7 pt to make the point layer compact. Each actual point consists of 12 concentric, unstroked, same-color translucent disks whose radial Gaussian alpha gradient creates a soft edge (relative-radius sigma 0.42, nominal central alpha 0.95). This gradient softens only each individual actual point; it performs no KDE or data smoothing and adds no synthetic observations. Tracks organize the dots without encoding a second variable; horizontal coordinates are not jittered, binned or rounded. Tukey boxplots are used: solid boxes show the 25th–75th percentiles (Q1–Q3) of elementwise APE, and elongated vertical lines crossing each box show the median of 50 APEs, also printed as Median to the right of each row. With IQR=Q3−Q1, thin whiskers and short caps extend to the smallest and largest actual observations within [Q1−1.5×IQR, Q3+1.5×IQR], including boundaries; fence values are not used directly as endpoints. Actual observations outside the whiskers remain fully plotted at their original coordinates, without duplicate outlier symbols. Means are not marked separately, and the figures do not depict confidence intervals. All statistics are computed after taking elementwise absolute values and describe the empirical distribution across parameter combinations rather than error bars across training seeds. All five methods share a zero-based linear horizontal axis within each figure: [0,300]% for ν and β, [0,110]% for γ, displaying every finite value in full. Each figure has one full-range panel. GIFT uses vivid deep blue, PDE-FIND deep orange, PDE-FIND-KC deep green, PINN-SR deep purple and PINN-SR-KC deep teal; dots and corresponding whiskers share method colors. Algorithm labels are bold black and axes are solid black. Dots, solid boxes and whiskers use their method's vivid dark color; median lines use exactly the box color, have width1.6 pt, cross and extend beyond the box, and are approximately 2.1 times the box height. Horizontal-axis ticks point upward into the plot while their numbers remain below the axis. The axis extends 3% of the current horizontal span beyond the rightmost tick, without changing data coordinates or tick locations. Whiskers are thin and caps short. The figures contain only algorithm names, coordinate ticks, a parameter-specific horizontal-axis title and per-method Median values; the text defines the statistics. All three figures and the main table use the same APE definition to compare error magnitudes and dispersion parameter by parameter, without depicting correlations among parameters. See the [point-coordinate CSV](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/source_points.csv) and [statistics CSV](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/source_statistics.csv) for individual errors and empirical statistics, and the [plotting metadata](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/figure_metadata.json) and [figure manifest](../results/formal/W3_single_trajectory_20261010/figures/parameter_distributions/figure_manifest.json) for complete plotting rules and file identities.

## Provenance and reproduction boundaries

Byte identities of inputs including the 50-case parameter CSV, protocol locks and ID0 arrays, and source/input/claim bindings for 250 slots, are in the W3 result package, run audit materials and `FINAL_SOURCE_AND_SCOPE_AUDIT.json`. Complete two-machine execution control, training states and external implementation code are not included in the GIFT project package. Users must download the corresponding upstream code from the [external algorithm repository registry](EXTERNAL_REPOSITORY_POLICY.md) and apply the adaptations described here and in the [manual adaptation instructions](EXTERNAL_MANUAL_ADAPTATION.md) outside the GIFT repository.
