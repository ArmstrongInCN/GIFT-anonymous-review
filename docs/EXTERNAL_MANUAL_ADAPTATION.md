# External algorithm downloads, manual adaptations and interfaces

The GIFT repository does not contain external algorithm implementations or automatic source patches. To use external baselines, download the pinned commits from the official repositories below, make the necessary adaptations described here **outside the GIFT repository folder**, and provide the interfaces specified in this document. Within GIFT, `adapters/__init__.py` only connects external interfaces; it does not define networks, integral equations, sparse regression or source rewriting.

The runtime interfaces used for experiments on this machine are stored in `../gift-external-runtime/`; the original official checkouts remain in their respective external directories. This directory is an independent local dependency, is not part of the GIFT Git repository and is not distributed with GIFT. New users cannot obtain these implementations from a GIFT clone; they must download official code, apply the adaptations below and provide the same interfaces. Installing GIFT alone is sufficient to read published result tables; retraining or inference with external methods also requires these dependencies.

## Directories and sources

| Path or environment variable | Purpose |
| --- | --- |
| `GIFT_EXTERNAL_ADAPTER_ROOT` | External runtime interface directory containing an `adapters/` subdirectory. Defaults to `gift-external-runtime/` beside the GIFT repository. Must not point to GIFT or any of its subdirectories. |
| `GIFT_EXTERNAL_ROOT` | Parent of the pinned FNO, U-NO, U-Net, PDE-FIND, PINN-SR and TensorFlow checkouts; subdirectory names are listed in `external_sources.json`. Must be outside GIFT. |
| `GIFT_ANIE_SOURCE_ROOT` | Direct path to the official ANIE checkout; `anie/` under the parent above can also be used. Must be outside GIFT. |
| Repository files `external_sources.json` and `anie_sources.json` | Provenance metadata including repository addresses, pinned versions and selected files; neither algorithm implementations nor executable adaptation patches. |

External runtime interfaces and official checkouts can occupy different external directories. When official files require changes, work in your own adapted copy outside the repository and record the original commit and modified files; retain a clean checkout for provenance checks. The local interfaces load from unmodified official checkouts and implement the current computational semantics explicitly declared below. Original numerical results, weights and protocol identities from completed experiments are retained separately; updating a training interface does not convert those results or recovery states to another protocol.

## FNO-2D / FNO-3D

1. Load `SpectralConv2d_fast` and `FNO2d` from `fourier_2d_time.py`, and `SpectralConv3d` and `FNO3d` from `fourier_3d.py`. Upstream examples read data and train at module level; isolate these executable examples behind separate entry points in an external adapted copy so that loading a network cannot trigger them. Preserve class definitions, spectral layers, forward computation and initialization order.
2. Adjust input dimensions at the unique `fc0` input projection in each model constructor. For single-initial-state W1/W2, change FNO-2D from 12 to **3**, comprising one field and two spatial coordinates; change FNO-3D from 13 to **4**, comprising one field and three space-time coordinates. The independent 46-frame-history protocol uses **48 / 49**, respectively. Determine dimensions before constructing the model; do not repeat an initial state to imitate historical frames or load 46-frame weights into a single-state model.
3. Retain FNO-2D modes=12/12, width=20 and FNO-3D modes=8/8/8, width=20. Provide the original `UnitGaussianNormalizer` and `LpLoss` from `utilities3.py`, isolating unrelated examples and data loading.
4. FNO-2D inputs use `[batch,Y,X,history]`, with the single-step output retaining a final one-channel axis. FNO-3D repeats observation channels along query time, using `[batch,Y,X,query_time,history]`; the original model appends coordinates and outputs the full query grid.
5. Training losses, curricula, normalization and model selection follow the GIFT experiment protocol and are separate from input projection changes. W2 FNO-3D retains the original 75 joint queries and then selects the first 25 future points; spatial normalizers use frozen training statistics through deterministic Fourier grid interpolation, without fitting the target grid or test population.

## U-NO

1. Retain the original `UNO`, `integral_operators`, `Adam` and `LpLoss` outside the repository; do not replace spectral computations, interpolation gradients or optimizer kernels. Load only the required loss definitions from utility files, without running example data loading.
2. Move the two module-level random-seed settings in `navier_stokes_uno2d.py` to the user's training entry point and set the protocol seed before model construction. Importing an external module must not reset the seed already set by the training entry point to zero; retain the original initialization method and parameter creation order.
3. Single-state W1/W2 constructor settings are in_width=5, width=32, pad=0, factor=0.75. The original network appends four periodic coordinate channels to the field. The 46-frame protocol uses in_width=50. Inputs and single-step outputs use `[batch,Y,X,channel]`.
4. During single-state training, feed each prediction directly into the next step and preserve all feedback gradients. Existing activation checkpoints use non-reentrant computation; do not alter BatchNorm state or update behavior, or change the physical batch. Current supervision spans 20 steps and evaluation recurses for 75; the protocol declares these budgets and learning-rate schedules separately.

## U-Net

1. Provide the original `U_net` class from external `Baselines/U-net.py`.
2. For W1/W2, use original constructor arguments input_channels=1, output_channels=1, kernel_size=3, dropout_rate=0; the 46-frame-history protocol changes only input_channels to 46. No convolution, BatchNorm, skip connection or initialization changes are needed.
3. Inputs and outputs use `[batch,channel,Y,X]`. Single-state closed-loop prediction feeds each output into the next step without truncating training gradients. Current four-step supervision and 75-step evaluation are experiment budgets, not the original authors' NS training script. N64/N96/N128 share one fully convolutional network; the physical scale represented by a pixel kernel changes with resolution.

## ANIE

1. Follow the pinned NS notebook's construction order to provide the `model_blocks` integral network, `SingleConvNeuralNet` encoder, `Decoder_NN_2D` decoder and original `Integral_spatial_attention_solver_multbatch`. Preserve Galerkin attention definitions while isolating upstream example training, plotting, unrelated ODE/Monte Carlo entry points and circular imports. Type annotations may be evaluated lazily; do not replace original classes or autograd with local reimplementations.
2. Correct coordinate ordering where space and time are concatenated in `Attentional_IE_solver.py` (around line 1190 in the pinned version): the state flattens from `[batch,space,time,channel]` with space-major/time-minor tokens; the original repeated spatial coordinates have `[batch,time,space,coordinate]` and must swap time and space before flattening. Time coordinates must retain the full contiguous query-time sequence for each spatial point; **do not sort repeated times**. For example, all times for spatial point 0 must precede all times for point 1, with coordinates matching states token by token. Preserve state ordering, integral normalization, iteration formulas and stopping rules.
3. At functional attention dropout in `linear_attention` in `Galerkin_transformer.py` (around line 758), bind dropout activation to the calling Dropout module's training state. Training retains the original functional dropout default probability **0.5**, rather than the passed module's annotated 0.1; evaluation disables this training dropout. Leave other dropout, attention and normalization unchanged.
4. Inputs are finite float32 initial vorticity fields of shape `[batch,64,64]`. The encoder produces a 16×16×32 latent space; retain the global decoder 8192→64→256→4096. Attention uses latent32, embedding64, 4 heads, 4 blocks, feedforward128 and module dropout 0.1; preserve original construction and parameter creation order. Spatial coordinates use a 16-point 0–1 axis; divide local physical query times of 0–3 seconds by 3 before passing them to the original integral solver.
5. Current `aligned_ns_single_v1` uses the original NS training c=0 branch: encode only the initial state, repeat the encoded state along query time as initial iterate y_init, and retain initialization=True, spatial_integration=True, use_support=False, accumulate_grads=True, at most 3 iterations, smoothing_factor=0.5 and global_error_tolerance=1e-6. Do not turn the encoded state into a fixed free term evaluated at every right-hand-side call, or add stepwise temporal feedback, residual anchoring or a local decoder.
6. Bind the solver's device global to the input device and keep model and inputs on that device in float32; do not migrate parameters during optimizer updates. Explicitly provide 76 query points for both current training and evaluation; the historical default of 151 points when times are omitted cannot be used for current W1 measurements. Original output is `[batch,time,64,64]`, including a predicted initial frame; do not overwrite it with the true initial field. Report the first-frame encoder/decoder reconstruction separately through `initial_decoder`.
7. ANIE participates only in W1. The fixed protocol specifies c=0/y_init training, joint Adam, validation-MSE-best selection, delayed scheduling, patience and other training rules; moving dependencies does not change them. Older `native_ns_single_v1` applies only the evaluation dropout correction, while older `aligned_legacy` also permits the historical fixed_f branch; load old weights with their recorded profile rather than silently switching their ordering.

Target locations: [NS notebook](https://github.com/emazap7/ANIE/blob/2071ad709b260a6c305450affcf7168fd825f692/NIE_Attention_Navier-Stokes_patches.ipynb), [solver](https://github.com/emazap7/ANIE/blob/2071ad709b260a6c305450affcf7168fd825f692/IE_source/Attentional_IE_solver.py#L1183), [attention](https://github.com/emazap7/ANIE/blob/2071ad709b260a6c305450affcf7168fd825f692/IE_source/Galerkin_transformer.py#L750), [original NS initialization](https://github.com/emazap7/ANIE/blob/2071ad709b260a6c305450affcf7168fd825f692/IE_source/experiments.py#L5295). These two computational corrections change the uncorrected function, so current results are experiments with the official architecture and declared corrections, not a verbatim reproduction of the authors' code.

## PDE-FIND

1. Provide the original `PolyDiffPoint`, `build_Theta`, `TrainSTRidge` and `STRidge` from external `PDE_FIND.py`, without executing top-level examples.
2. For all NumPy versions, replace the unique `STRidge` comparison with an empty list used to test whether biginds is nonempty with an explicit nonzero index-length check. NumPy 1.26 already raises an error because the array and empty list have incompatible shapes; this change is not limited to NumPy 2. The explicit test restores the final least-squares step described by the original comment. Older NumPy comparisons with a single-element array could incorrectly skip this step, so bitwise equivalence to old behavior cannot be claimed for every degenerate input. Do not also change threshold search, candidate acceptance or the least-squares solver.
3. Preserve the original seed0 MT19937 sample set and order, using a local RNG to avoid altering other models' global random state. Boolean index tables may accelerate membership tests but must not change selected samples, ordering or train/test sets.
4. The GIFT data interface retains the declared periodic velocity reconstruction, separate SVD of vorticity and velocity under noise, fifth-degree local polynomial derivatives and mixed derivatives. Library rows follow y,x,time, with 4 known-library columns or 90 open-library columns. Data processing and library geometry are experiment settings, not equivalent format conversions.
5. In the current formal W3 experiment with 50 noise-free parameter combinations, each case's data container contains exactly 1 training trajectory (local ID0) for that combination and 0 validation trajectories. Each parameter case uses its own trajectory, without duplication or reuse across cases. PDE-FIND reads that case's 501×64×64 float32 vorticity values and t=0–10 time grid at intervals of 0.02. Do not duplicate ID0 to reach 50 trajectories or alter derivatives, candidate libraries, sampling or STRidge settings. Noise-free cases do not use SVD denoising.

## PINN-SR and TensorFlow optimizers

1. Provide the original `PhysicsInformedNN` from the pinned EQDiscovery file outside the repository, isolating example data loading, training and global environment settings. Use `tf.compat.v1` graph mode and provide the original `NadamOptimizer` and `ScipyOptimizerInterface` from the pinned TensorFlow checkout; do not rewrite optimizer kernels or import the entire TensorFlow source tree to build it.
2. Change the first dimension of the unique lambda_w coefficient vector from 60 to 4 for the known library or 90 for the open library. The known library contains vorticity, advection, Laplacian and known forcing mode in that order. The open library retains the original 60 columns and appends 30 columns by multiplying q, q², u q, v q, w q, in that order, by the original six derivative factors; q is −4 cos(4y). Column order and names must match weights and coefficient readout.
3. Preserve original Xavier initialization, seed1234, three coordinate inputs, 8 hidden layers of width 60 and three field outputs; use float32 graph computation with TF32 disabled. Use a single-threaded Session as specified, with explicit CPU/GPU selection and a memory-growth policy. Default `native_fp32` retains original coordinate autodifferentiation, powers and losses; every original NAdam update uses the full population of 24,000 observations/84,000 collocation points.
4. Enable TF1 reference-variable semantics before graph construction and verify that both network variables and original NAdam state are RefVariable. Original TF1 `ScipyOptimizerInterface` evaluates losses and gradients by feeding candidate variables; compat graph mode with ResourceVariable alone can leave candidates outside the actual computation. After graph construction and compilation, compare objectives and all gradients under candidate feeds and explicit assignments, then verify that real finite-step L-BFGS changes parameters. Record SciPy success, status, message, nit, nfev, njev, initial/final losses and gradients; reaching a limit or returning from an interface is not convergence.
5. Independent sparse regression calls original `TrainSTRidge` and `STRidge`. Preserve the original seed0 MT19937 sample set and returned order without sorting training rows; retain the float32 inherited coefficient snapshot read from TF without an extra float64 conversion, and carry the first-round l0 baseline into subsequent rounds. Retain rcond=−1 for least squares and use index length for the unique empty-index test. Isolate sampling with a local RNG without altering selection order or values.
6. Keep lambda_w as a stable variable. Immediately after every STRidge round, explicitly assign and save its vector and exact nonzero support. Ordinary coefficient, metric and log reads must not assign implicitly. ADO follows [paper Methods equation (6b)](https://www.nature.com/articles/s41467-021-26434-1), fixing regression coefficients and updating only network weights/biases; use the same original NAdam with existing network momentum and beta state rather than recreating the optimizer. The pinned official executable NS script uses joint ADO and delayed assignment, which differs from the paper's subproblem. Current training declares `paper_ado_v1` and does not claim event-by-event reproduction of that script.
7. Post-training starts from the final STRidge vector and support, fixed by the original exact zero/nonzero rule without an additional threshold. Jointly update the network and active coefficients according to paper equation (8), using original coefficients multiplied by the fixed mask for both residuals and readout. Retain original momentum; excluded entries' raw storage may advance under old momentum, but effective coefficients must remain exactly zero, and support must not be reconstructed from the evolved raw vector. Recover the model, optimizer slots, mask, final regression vector/support, RNG and phase state together. Save a boundary before entering L-BFGS and redo an uncommitted phase from that boundary after an internal interruption; do not claim continuation of the solver's internal state or use old joint-ADO results as recovery state for the corrected implementation.
8. Optional `optimized_xla_fp32` changes only equation evaluation and compilation: KC propagates exact first derivatives and the Laplacian through the original tanh network while retaining parameter autodifferentiation; the open library combines coordinate derivatives and equivalently factors the contraction of 90 terms from the original 15 polynomial/forcing factors and 6 derivatives, still providing the full 90-column Phi to STRidge. Disable TF32, use no half precision and do not reduce observations, collocation points or training updates. Explicit GPU selection and XLA configuration must precede the first TF import; prepare libdevice outside the repository for the environment. After compilation, recheck candidate propagation, all gradients and optimizer state; claim speed and accuracy benefits only after complete paired training from the same initial state passes prediction, physical-residual, support and active-coefficient gates. Record execution mode in provenance metadata; strict native FP32 remains the default.

## External interface contract

Provide Python modules in a directory named `adapters/` under the external root. The following interfaces connect GIFT training and evaluation; users implement all algorithm classes and source adaptations externally. Existing training entry points may call internal helpers, whose names must also be retained.

| External module | Required names and behavior |
| --- | --- |
| `models` | `build_model`, `load_checkpoint`, `source_record`; also `fno_utilities`, `uno_components`, `_fno_class`, `_import_file`. Load original networks and utilities for the declared method/history/device and load model state strictly; attach a `gift_external_source` provenance record to the model. |
| `prediction` | `load_uno`, `load_unet`, `uno_rollout`, `unet_rollout`, providing the 46-frame-history interface and rollouts using prediction-only feedback. |
| `w1_extended` | `build_network` and `forward_model`; history=1, input `[B,Y,X]`, output `[B,steps+1,Y,X]`, with the supplied true initial state first and closed-loop future predictions; retain full training feedback gradients as specified. |
| `anie_config` | `ANIEConfig`, `PINNED_COMMIT`, `source_identity` and source-lock readers; return the pinned architecture and recorded profile, rejecting unsupported architectures or branches. |
| `anie` | `ANIEPredictor`; provide standard PyTorch parameter/state interfaces, `forward(initial,times)`, `initial_decoder(initial)`, `source_identity()` and `last_solver_iterations`, using the original NS computational branch specified above. |
| `pde_find` | `load_upstream`, `source_record`, observation and periodic-data processing, library generation, regression and parameter-readout interfaces; preserve 4/90-column conventions and provenance. |
| `pinn_runtime` | `PINNRuntime`, `read_inputs`, original Session phase operations and variable export/recovery; execute the original algorithm without a local imitation network. |
| `pinn_stridge` | `fit_stridge`, accepting finite float32 matrices/targets, 4- or 90-dimensional inherited coefficients, ADO round order and a fixed l0 penalty; return coefficients, acceptance history, selected threshold, inputs and provenance. |
| `pinn_reference` | `read_checkpoint`, `read_reference` and declared library/budget metadata; read coefficient results without executing TensorFlow training. |
| `check` | Independent small-scale model-construction checks for loadability and shape, not evidence of complete scientific results. |

Initialization randomness, parameter names and creation order, input/output axes, dtype/device, gradient connectivity, train/eval behavior, checkpoint profile, normalization statistics and library column order are all parts of the interface. Matching names alone does not establish computational equivalence. After changing an external interface, first construct models with the same seed and compare all state, compare forward values/gradients on fixed inputs, then check fixed trajectories with saved formal weights. Preserve completed scientific data, original predictions, model weights and provenance metadata; moving source directories does not permit parameter changes or retraining as substitutes for equivalence checks.
